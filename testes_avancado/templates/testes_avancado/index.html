🧪 Testes Avançados (pytest)

Fixtures, parametrize, mocks, os três níveis de teste e cobertura de código. Diferente dos outros apps, aqui os exemplos são arquivos de teste de verdade, rodados com o pytest (não há funções demo_* no shell). Os arquivos estão em:

testes_avancado/test_parametrize.py
testes_avancado/test_mocks.py

testes_avancado/test_integracao.py
testes_avancado/test_e2e.py
testes_avancado/servicos.py
pytest -v                      # suíte inteira
pytest -m unitario -v          # só um nível
coverage run -m pytest         # mede cobertura
coverage report -m
coverage html

1. Fixtures

Preparam dados e dependências reutilizáveis. Basta declarar um parâmetro com o nome da fixture que o pytest injeta o resultado. Uma fixture pode depender de outra, e o conftest.py as disponibiliza para todos os testes da pasta sem import. Com yield, tudo antes é setup e tudo depois é teardown, que roda mesmo se o teste falhar. O escopo (function, module, session) define quantas vezes ela é recriada.

Ver: conftest.py, test_fixtures.py

2. parametrize

Roda o mesmo teste várias vezes com entradas diferentes, sem duplicar código. ids= dá nomes legíveis a cada caso, e empilhar dois decorators gera o produto cartesiano das combinações. O pytest pode reordenar a execução (agrupa por fixtures de escopo maior), então cada teste precisa ser independente dos outros.

Ver: test_parametrize.py

3. Mocks

Substituem uma dependência externa por um dublê controlado, evitando rede, lentidão e efeitos colaterais reais. Regra de ouro: faz-se o patch do nome onde ele é usado, não onde foi definido. return_value simula um resultado, side_effect simula uma falha, e assert_called_once_with verifica o comportamento, incluindo o que não deve acontecer. monkeypatch altera ambiente e atributos, com reversão automática.

Ver: test_mocks.py, servicos.py

4. Unitário vs Integração vs E2E

A diferença está em quanto do sistema o teste atravessa. Unitário: uma peça isolada, sem banco, muito rápido. Integração: várias peças reais juntas (serializer, ORM, signal), com banco. E2E: o fluxo completo via HTTP, como um cliente da API faria. Os markers do pytest.ini permitem rodar cada nível separado, e é assim que se separa a suíte rápida (a cada commit) da lenta (no CI).

Ver: test_unitario.py, test_integracao.py, test_e2e.py

5. Cobertura de código

Mede quais linhas foram executadas pelos testes e aponta o código que nenhum teste tocou. Com branch = True mede também os desvios (cada lado de um if). Cobertura alta não prova ausência de bugs: mede o que foi executado, não o que foi verificado. O bug do validate() no PATCH parcial tinha a linha coberta e só apareceu quando um teste exercitou o caso certo.

Ver: .coveragerc, relatório em htmlcov/index.html
