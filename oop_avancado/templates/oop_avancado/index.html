1. Herança múltipla e MRO

Quando uma classe herda de mais de uma, o Python usa o algoritmo C3 linearization pra decidir a ordem de busca de métodos — isso é o MRO (Method Resolution Order). super() não significa "minha classe pai": significa "o próximo na fila do MRO". É isso que viabiliza herança cooperativa (todas as classes da cadeia participando de uma chamada só).

Ver: Motor, SistemaEletrico, Carro, demo_mro()

2. classmethod vs staticmethod vs instance method

  • instance method — recebe self, acessa dados da instância
  • classmethod — recebe cls, muito usado como construtor alternativo (ex: .da_string(...))
  • staticmethod — não recebe nem self nem cls; é uma função utilitária que só "mora" na classe por organização

Ver: Funcionario, demo_classmethod_staticmethod()

3. @property

Permite expor um método como se fosse um atributo simples (obj.saldo, sem parênteses), mas com validação por trás. É a forma "pythônica" de fazer getter/setter — em vez de get_saldo()/set_saldo() como em outras linguagens.

Ver: ContaBancaria, demo_property()

4. Dunder methods

Métodos com __nome__ definem como o objeto se comporta com operadores e funções nativas do Python:

  • __repr__ — como o objeto aparece em print()/debugger
  • __eq__ — como == compara duas instâncias
  • __hash__ — necessário pra colocar o objeto em set ou usar como chave de dict (se você define __eq__, precisa redefinir __hash__ também)
  • __add__ — como o operador + se comporta entre duas instâncias

Ver: Ponto, demo_dunder()
