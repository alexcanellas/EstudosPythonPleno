🔒 Context Managers

O protocolo __enter__/__exit__, a versão com @contextmanager e por que o __exit__ roda mesmo quando dá exceção. O código de verdade está em:

context_managers/exemplos.py

Roda as funções demo_* no shell do Django:

python manage.py shell
>>> from context_managers.exemplos import *
>>> demo_context_manager_classe()

1. Protocolo __enter__ / __exit__

Um context manager é qualquer objeto com dois métodos: __enter__ roda ao entrar no with (o que ele retorna vira o as x), e __exit__ roda ao sair, sempre — com ou sem erro. É isso que garante liberação confiável de recursos (arquivos, conexões, locks).

Ver: Cronometro, demo_context_manager_classe()

2. __exit__ roda mesmo com exceção

Esse é o ponto principal: o __exit__ é chamado até quando o código dentro do with quebra. É assim que with open(...) fecha o arquivo mesmo se der erro no meio da leitura. Retornar True no __exit__ "abafa" a exceção; False/None deixa ela continuar propagando.

Ver: RecursoComErro, demo_context_manager_com_excecao()

3. @contextmanager — versão com generator

Em vez de escrever uma classe inteira, uma função geradora resolve: tudo antes do yield é o __enter__, o valor do yield é o as x, e tudo depois (dentro de um finally) é o __exit__.

Ver: cronometro_simples(), demo_contextmanager_decorator()

4. Múltiplos context managers no mesmo with

Dá pra abrir vários de uma vez (with a, b:). A ordem de entrada é da esquerda pra direita, e a ordem de saída é o inverso — como uma pilha (o último que entrou é o primeiro que sai).

Ver: bloco(), demo_with_statement_multiplo()
