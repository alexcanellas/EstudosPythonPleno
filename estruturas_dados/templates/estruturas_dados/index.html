🗂️ Estruturas de Dados Internas

Como list, dict e set funcionam por dentro, e por que a complexidade de cada operação importa na prática. O código de verdade, comentado, está em:

estruturas_dados/exemplos.py

Roda as funções demo_* no shell do Django:

python manage.py shell
>>> from estruturas_dados.exemplos import *
>>> demo_complexidade_lista()

1. List — array dinâmico

Por dentro, uma list é um array (bloco contíguo de memória com ponteiros pros objetos), com espaço extra reservado pra evitar realocar a cada append. Isso define a complexidade de cada operação:

lista[i]              -> O(1)   acesso direto por índice
lista.append(x)       -> O(1)*  amortizado
lista.insert(0, x)    -> O(n)   empurra tudo pra direita
lista.pop()           -> O(1)   remove do final
lista.pop(0)          -> O(n)   remove do início
x in lista             -> O(n)   varre item por item

Ver: demo_complexidade_lista()

2. Dict — hash table

Um dict guarda pares (hash da chave → valor) numa tabela hash. É isso que torna dict['chave'] O(1) em média, independente do tamanho. Consequência: a chave precisa ser hashable (imutável) — por isso tuple pode ser chave, mas list não pode.

Ver: demo_dict_hash()

3. Set — a mesma hash table do dict

set usa por baixo dos panos a mesma estrutura de hash table do dict, só que sem valor associado — só as chaves. Por isso x in set é O(1) médio, bem diferente de x in list, que é O(n). É também isso que viabiliza as operações de conjunto (união, interseção, diferença) de forma eficiente.

Ver: demo_set_operacoes()

4. Benchmark real: list vs set

Não é só teoria — dá pra medir com timeit. Numa lista com 100 mil elementos, buscar o último item é o pior caso possível pra uma list (O(n)), enquanto o set resolve em tempo praticamente constante (O(1)). A função abaixo imprime quantas vezes o set foi mais rápido, na prática.
